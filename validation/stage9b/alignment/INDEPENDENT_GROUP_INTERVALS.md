# Интервалы по независимым группам

Статус: экспериментальная диагностика; физическая приёмка не завершена.

Три seed внутри одной группы используют общие обучающие шаблоны. Поэтому
разброс трёх результатов нельзя автоматически считать разбросом независимых
наблюдений. Следующий кандидат использует 12 независимых групп по три seed.
Шаблоны и положения максимумов строятся отдельно в каждой группе. Производные
усредняются до обращения в градиентную толщину. Повторная выборка целых групп
сохраняет зависимость внутри группы.

## Совмещение плотности

Опция `--center-profile` совмещает итоговый средний профиль по уровню 50%.
Каждая повторная выборка также совмещается заново. Для этого сначала сохраняется
профиль на интервале `[-11, 11]`, затем сравнивается участок `[-10, 10]`.
Если перенесённый участок выходит за измеренные координаты, расчёт выдаёт ошибку.
Экстраполяция и изменение пространственного масштаба запрещены. Ширина и
градиентная толщина от этого переноса не меняются.

Исходный режим без дополнительного совмещения сохранён для воспроизводимости
[первого пилота](shock-ensemble-coverage-pilot.json). Его результаты нельзя
смешивать с новой проверкой.

## Расширенная синтетическая проверка

Проверяются logistic и Gompertz, временная корреляция 0 и 0,8, пространственная
корреляция 0 и 0,2, шум 1,5% и 3%. Всего 16 сценариев по 128 повторов,
в каждом повторе — 12 групп по три seed и 1024 повторные выборки групп.
Для каждого сценария отдельно учитываются покрытие статистических интервалов,
покрытие с чувствительностью к обработке и одновременное покрытие плотности.
Частота покрытия на конечной выборке не доказывает точное покрытие 95%.
Эта проверка использует 64 окна; она не квалифицирует автоматически анализ
половин серии по 32 окна и попарные сравнения физических вариантов.

Команда из корня рабочей копии, с установленными зависимостями анализа:

```sh
OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 python tools/calibrate_shock_ensemble.py \
  --output output/shock-ensemble-centered-coverage-v2.json \
  --jobs 4 --replicates 128 --matrix --center-profile --seed-start 14000000
```

Новые запуски сохраняют каждый повтор в соседний каталог `.parts`. После
прерывания та же команда с `--resume` использует сохранённые результаты,
проверяя параметры и хеши исходников. Уже готовый итоговый JSON не перезаписывается.
Первый расширенный запуск был начат до добавления checkpoint и прервался
на 77-м повторе последнего сценария: Gompertz, корреляции 0,8/0,2, шум 3%.
Итогового JSON нет; журнал `output/shock-ensemble-centered-coverage.log`
сохранён. По завершённым строкам журнала нельзя восстановить частоты покрытия.

Отказ воспроизведён отдельно: fixture seed 14007606, группа 6, проверяемый seed
с индексом 2, окно 43. Два локальных минимума отличаются по сдвигу на 0,30,
а по функции потерь — примерно на 0,84%. Это соответствует существующему
критерию неоднозначности. Его не ослабляли; выбор одного из минимумов не делали.
Подробности: [shock-ensemble-ambiguity.json](shock-ensemble-ambiguity.json).

Повторный запуск `v2` использует те же исходные seed и тот же оцениватель.
Теперь отказ оценивателя сохраняется как отдельный результат и считается
непокрытием во всех долях: знаменатель включает все запланированные повторы.
Итоговый статус при наличии отказов — `coverage_study_with_failures`.
Неожиданные ошибки исполнения по-прежнему останавливают запуск; завершённые
checkpoint позволяют продолжить его. Это исправление диагностики, а не
устранение неоднозначности профиля.

Запуск `v2` завершён: 2048/2048 повторов, один отказ. Прежний интервал ширины
имеет недостаточное покрытие в части сценариев. Итоги, парные контрольные
проверки причин и новый кандидат описаны в [следующем отчёте](ENSEMBLE_WIDTH_BAND.md).

## Подготовка независимых физических повторений

`shock_validation.py --seeds S1 S2 S3` задаёт три разных положительных 31-битных
seed. Они записываются в `validation.json` и используются анализаторами MC3D
и SPARTA. Продолжение серии с другими seed запрещено. Старые отчёты без этого
поля используют прежние 123, 456, 789.

Для независимых групп seed не должны повторяться между группами. Наличие
трёх разных seed внутри каждой группы само по себе этого не гарантирует.
До запуска всей кампании нужны проверка независимости групп, совпадения
бинарных файлов и условий, а также обоснование ожидаемой точности.
Допуски исходной приёмки не меняются.

Проверено: 94 Python-теста; отдельный запуск с двумя повторами на форму
создал checkpoint, а `--resume` восстановил итоговый JSON байт-в-байт без
перезаписи checkpoint. Этот короткий запуск проверяет возобновление, а не покрытие.
