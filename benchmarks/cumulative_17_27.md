# Суммарный эффект оптимизаций PR #17–27

Сравнение `99b0d18` (перед #17) и `aa3e43a` (после #27). Код солвера для измерений не менялся.
Обе версии собраны GCC 14.2.0 Release на одном Ubuntu 24.04 runner и прошли собственные тесты: 90/90 до, 118/118 после.
Runner: AMD EPYC 7763, доступны 4 логических CPU (2 ядра × 2 SMT-потока). Режим 8 рабочих потоков превышает доступные аппаратные потоки; его результат нельзя трактовать как масштабирование на 8 ядрах.
Полное окружение, флаги, SHA и диапазоны прогонов сохранены в [JSON](cumulative_17_27.json).
[Полные артефакты и логи](https://github.com/room89/mc3d/actions/runs/41069864457).

## Методика

Малая сетка: 24×12×8, np=60; большая: 48×24×16, np=120. Конечное модельное время 0,05.
Seed 123/456/789; пять чередующихся измеряемых прогонов каждой версии и один прогрев перед каждой серией.
Все сценарии выполнялись последовательно. Снимки и необязательный файловый вывод отключены.
RSS — пик всего процесса по `/usr/bin/time`, КиБ. Диагностика численности выполнена отдельно со снимками и исключена из замеров.
Каждая строка времени — медиана пяти прогонов одного seed. × = время до / после; сокращение = (1 − после / до) × 100%.
Диапазоны приведены как минимум–максимум, не как доверительные интервалы. Проценты отдельных PR не складываются.
Старый RNG — mt19937, новый — PCG32; одинаковый seed не означает одинаковые траектории. Инлайнинг также мог изменить округление.
При сравнении учитывайте число шагов, достигнутое время и фактическое число частиц; нормализация на шаг не устраняет всех различий нагрузки.

## Воспроизведение

Создать два checkout по указанным полным SHA. Для обоих использовать `CC=gcc-14 CXX=g++-14`, `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release`, затем сборку и `ctest --test-dir build --output-on-failure`.
Инструменты брать из этого PR; пути к бинарникам — абсолютные. Выходные каталоги должны быть новыми.

```sh
python3 tools/benchmark_solver.py --baseline /path/baseline/build/MC3dSolver --binary /path/current/build/MC3dSolver --out results/small --threads 1 4 8 --seeds 123 456 789 --repeats 5 --warmups 1 --rss --diagnostics
python3 tools/benchmark_solver.py --baseline /path/baseline/build/MC3dSolver --binary /path/current/build/MC3dSolver --out results/large --grid 48 24 16 --particles 120 --geometries none --threads 1 4 8 --seeds 123 456 789 --repeats 5 --warmups 1 --rss --diagnostics
```

Для пустых сеток скомпилировать `tools/benchmark_cell_storage.cpp` против mc3d_core каждой ревизии по команде в начале файла (GCC 14, -O3), затем вызвать `tools/benchmark_cell_storage.py --baseline /path/baseline-probe --binary /path/current-probe --out results/memory`.
На машине должно хватать памяти для старого mt19937 на сетке 80³; версии запускать последовательно. Новые проверки инструментов: `python3 -B -m unittest discover -s tools -p "test_benchmark*.py"`.
