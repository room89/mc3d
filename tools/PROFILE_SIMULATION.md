# Диагностика памяти и задержек

Запуск из рабочего каталога расчёта, с абсолютными путями к solver и конфигу:

```sh
python3 /path/mc3d/tools/profile_simulation.py --out /path/results/profile-001 --interval 1 -- /path/MC3dSolver --config /path/config.json
```

Каталог `--out` должен быть новым. Стандартная библиотека Python, macOS/Linux;
команда передаётся без shell, рабочий каталог и конфиг solver не меняются.
Вывод сохраняется в `run.log`, не дублируется в терминал. Ctrl+C передаётся группе
дочернего процесса, частичный отчёт сохраняется. Код возврата совпадает с solver
(для сигнала — 128 + номер); ошибка сборщика даёт 1. Существующий визуализатор
`monitor_simulation.py` независим от обёртки.

Для исходного тяжёлого сценария использовать ту же команду с путём к
`configs/hypersonic_wadge_test.json`. Такой запуск при проверке PR не выполнялся.

## Файлы результатов

- `metadata.json`: команда, cwd, платформа, PID, интервал, код завершения и ошибки;
  availability означает доступность метрики хотя бы в одном отсчёте.
- `run.log`: исходные объединённые stdout/stderr без преобразований.
- `events.jsonl`: шаги, завершения фаз и число уходящих частиц; время получения
  относительно старта обёртки по монотонным часам.
- `samples.jsonl`: процесс/система, длительность сбора, дельты накопительных
  счётчиков, сбросы, причины недоступности. Время отсчёта — середина сбора.
- `summary.json` и `summary.md`: медиана/p95/максимум времени шага, максимальный
  наблюдённый RSS, десять медленных шагов с фазами, неполные шаги и инициализация.
  JSON содержит окна и диапазоны системных метрик для каждого шага.

Размеры — байты, время — секунды. CPU — суммарное время потоков процесса;
`cpu_percent` нормирован на одно ядро и может превышать 100%. p95 — nearest-rank.

## Источники и ограничения

Linux: `/proc/<pid>/stat` (RSS, CPU, minor/major faults), `/proc/meminfo` (доступная
память, swap), `/proc/vmstat` (swap in/out), `/proc/pressure/memory` (PSI при наличии).
macOS: `ps` (RSS, CPU), `vm_stat` (свободная память, компрессия, page/swap in/out),
`sysctl vm.swapusage`. Размер страницы берётся из системы. Команды используют
локаль C и таймаут по секунде. На macOS MemAvailable и faults процесса недоступны;
системные faults не подставляются вместо них. compressed_bytes — физическая память
компрессора; compression/decompression bytes — число обработанных страниц × размер.

Недоступное значение — `null`, не ноль. Ошибка источника записывается в отсчёт и
не прерывает solver. Сброс счётчика делает соответствующую дельту окна неизвестной.
Системные swap/компрессия/PSI зависят и от других процессов. Занятый swap без новых
swap-in/out не доказывает подкачку во время задержки; корреляция не доказывает причину.

Максимум отсчётов RSS не равен пиковому RSS. Окно шага включает ближайшие отсчёты до
начала и после конца; соседние окна могут перекрываться, их дельты нельзя складывать.
Шаг короче интервала отмечен coarse, неполное покрытие — incomplete_coverage,
разрыв более 1,5 интервала — sampling_gap. У первого отсчёта дельты неизвестны.

Календарное поле logger не используется. Получение строки включает задержку pipe
и планирования. Начало фазы оценивается как время получения завершения минус её
длительность: это приблизительное сопоставление, не точный profiler. Строки свыше
64 КиБ и последняя строка без перевода строки сохраняются, но не разбираются.
Обёртка не хранит сырой лог в памяти; отчёт читает только отсчёты и события.

## Проверка

```sh
python3 tools/benchmark_profile.py --binary /path/MC3dSolver --config configs/benchmark_body_check.json --out /path/overhead-np20 --threads 4
python3 -m unittest discover -s tests/python -v
```

Для np=80 взять копию конфига с изменённым np. Benchmark выполняет прогрев и пять
чередующихся пар; seed=123, end_time=0,05, снимки отключены. Полное время обёртки
включает отчёт. При накладных расходах >5% повторить с `--repeats 10` в новом
каталоге и исследовать причину. Снимки проверять отдельно: `--snapshots --threads 1`.
